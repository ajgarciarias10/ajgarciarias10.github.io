Revisión de usabilidad de F1-BUGAMBRA

Evaluación de la aplicación con los principios del Tema 1: Introducción a la IPO (pp. 16–48). Capturas reales antes/después de las correcciones.

Resumen ejecutivo

La aplicación tiene una base sólida (clasificación pública, adaptación móvil, PWA instalable), pero presenta fallos que contradicen los principios de usabilidad del tema 1. Se han corregido los más críticos: mensajes de error técnicos, navegación con estado recuperable, foco visible, modales accesibles y distinción entre fallo de red y datos vacíos.

Detalle de hallazgos y correcciones

1. Autenticación — Recuperabilidad y control del usuario (pp. 41, 44)

Antes: Al fallar el acceso, se mostraba el código técnico auth/invalid-credential. El usuario no sabía qué hacer. En registro, no se indicaba la longitud mínima y las etiquetas no estaban asociadas a los campos (labels: 0 en la inspección).

Después: authFeedback.ts traduce cada código a una instrucción accionable («Revisa el correo y la contraseña o utiliza "¿Olvidaste tu contraseña?"»). El formulario tiene , autocomplete, minlength, botón mostrar/ocultar contraseña y estados de carga diferenciados por operación.

2. Ficha de carrera (modal) — Robustez, control y consistencia (pp. 42, 43)

Antes: El modal era un div fijo que no se cerraba con Escape, no atrapaba el foco, y al recargar se perdía. La barra de pestañas móvil se superponía al contenido. Los botones de votar usaban opacity-40 sin cursor: default, y no había confirmación de voto.

Después:

nativo vía createPortal en document.body, cierre con Escape, foco inicial en el título, scrollToTop configurable, aria-pressed en votos, mensaje «Tu voto se ha guardado», cursor: default en deshabilitados, texto «X votos» en lugar de solo número.

3. Navegación y estado — Adecuación de tareas (p. 46)

Antes: Cambiar de pestaña o temporada no actualizaba la URL. Recargar volvía a «Clasificación» y temporada activa, perdiendo el contexto del usuario.

Después: useSearchParams sincroniza ?tab=…&temporada=…. Compartir o recargar restaura exactamente la vista. El foco salta al encabezado de contenido tras cambiar de pestaña.

4. Carga de datos — Robustez y tiempo de respuesta (pp. 43, 45)

Antes: Al bloquear Firestore, la app mostraba «Sin datos de temporada», confundiendo un fallo de red con una liga vacía. No había reintento manual.

Después: Listeners con includeMetadataChanges detectan fromCache. Tres estados: carga, datos de caché (aviso ámbar con botón «Reintentar carga»), error de red. Si hay datos se muestran aunque estén desactualizados; si no, mensaje neutro.

5. Accesibilidad transversal — Consistencia y carga cognitiva (pp. 42, 47)

Antes: Foco visible solo en algunos elementos. Textos de navegación en móvil truncados (Clasific.). Contraste de mensajes de éxito/error bajo en tema oscuro.

Después: :focus-visible global con anillo ámbar + sombra oscura. Etiquetas completas en móvil («Clasificación», «Resultados»). role="status"/alert en mensajes. Contraste mejorado en alertas.

Principios del Tema 1 que la app ya cumple (fortalezas)

  • Facilidad de aprendizaje — Familiaridad (p. 39): Clasificación, Equipos, Resultados usan metáforas deportivas conocidas; iconos consistentes (BarChart3, Shield, Flag).
  • Flexibilidad — Control del usuario (p. 41): Navegación por pestañas superior + barra inferior móvil; instalación PWA opcional explicada en /instalar.
  • Consistencia interna (p. 42): sport-panel, rail-title, m-card, m-row reutilizados en dashboards y vistas públicas.
  • Robustez — Condiciones adversas (p. 43): prefers-reduced-motion respetado en animaciones; safe-area-inset para notch/isla dinámica; touch-action: manipulation.
  • Adecuación de tareas (p. 46): Clasificación pública sin login; dashboards por rol (admin/jeque/piloto/usuario) con rutas protegidas.

Pendiente de validar con cuentas reales (fuera del alcance de esta revisión)

Los siguientes flujos requieren cuentas de cada rol para evaluar completamente:

  • Dashboard Jeque — gestión de escudería, fichajes, presupuesto
  • Dashboard Piloto — votación, estadísticas personales, rivalidades
  • Dashboard Usuario — predicciones, foro, sugerencias
  • Dashboard Admin — panel de control, usuarios, economía, rivalidades
  • Subasta en vivo — sincronización temps réel, pujas, timer

La presente revisión cubre la portada pública, autenticación, navegación, resultados y carga de datos —los puntos de contacto comunes a todos los roles—.

Cómo verificar los cambios localmente

  1. cd ~/Documentos/F1-BUGAMBRA
  2. cp .env.example .env.local (añade tu GEMINI_API_KEY)
  3. corepack npm install
  4. corepack npm run dev → http://localhost:3000
  5. Prueba: portada → Resultados → Split 2 → click en carrera → modal → Escape
  6. Prueba: Acceder → Registrarse → contraseña < 6 chars → error nativo
  7. Prueba: Acceder → correo/contraseña inválidos → mensaje comprensible
  8. Prueba: cambiar pestaña/temporada → recargar (F5) → se restaura
  9. Prueba: herramientas de red → Offline → portada → aviso ámbar + Reintentar
